## Submit application

Create a `DRAFT` application or submit straight to `SUBMITTED` if the doc checklist is
complete.

```
POST /developers/lending/v1/applications
```

**Request**:

```json
{
  "merchant_id": "merch_2j8…",
  "shop_id": "65df8abc123…",
  "amount_requested": "50000.00",
  "currency": "USD",
  "term_months": 12,
  "purpose": "inventory",
  "submit": false,
  "documents": [
    { "type": "merchant_identity", "s3_key": "uploads/identity/abc.pdf" },
    { "type": "psp_account_link", "psp": "stripe", "account_id": "acct_1Nxxxxx" }
  ]
}
```

| Field | Required | Notes |
|---|---|---|
| `merchant_id` | yes | Droplinked merchant id |
| `shop_id` | yes | Droplinked shop id |
| `amount_requested` | yes | String to preserve decimal precision |
| `term_months` | yes | 3, 6, 12, 18, 24 |
| `purpose` | yes | `inventory` \| `marketing` \| `working_capital` \| `other` |
| `submit` | no | `true` = transition to `SUBMITTED` if doc checklist complete; default `false` (stays `DRAFT`) |
| `documents[]` | conditional | Required when `submit: true`; checklist derives from cohort |

**Response (`201 Created`)**:

```json
{
  "id": "lapp_2qZf…",
  "state": "DRAFT",
  "cohort": "A_MOR_SHOPSADIQ_VIA_TELR",
  "mor_entity": "shopsadiq",
  "tier": "Tier1_CredibleX",
  "amount_requested": "50000.00",
  "currency": "USD",
  "term_months": 12,
  "doc_checklist": {
    "required": ["merchant_identity", "psp_account_link", "settlement_history_90d"],
    "received": ["merchant_identity", "psp_account_link"],
    "missing": ["settlement_history_90d"]
  },
  "inventory_os_signals": {
    "gmv_90d": "184500.00",
    "sell_through_velocity_score": 0.78,
    "return_rate_30d": 0.038,
    "attested_skus": 142
  },
  "created_at": "2026-06-01T12:00:00.000Z"
}
```

### curl

```bash
curl -X POST https://apiv3.droplinked.com/developers/lending/v1/applications \
  -H "Authorization: Bearer ds_test_REPLACE_ME" \
  -H "Content-Type: application/json" \
  -d '{
    "merchant_id": "merch_2j8…",
    "shop_id": "65df8abc123…",
    "amount_requested": "50000.00",
    "currency": "USD",
    "term_months": 12,
    "purpose": "inventory",
    "submit": false
  }'
```

### TypeScript

```ts
import { DroplinkedClient } from "@droplinked/sdk";

const droplinked = new DroplinkedClient({
  apiKey: process.env.DROPLINKED_API_KEY ?? "ds_test_REPLACE_ME",
});

const application = await droplinked.lending.applications.create({
  merchantId: "merch_2j8…",
  shopId: "65df8abc123…",
  amountRequested: "50000.00",
  currency: "USD",
  termMonths: 12,
  purpose: "inventory",
  submit: false,
});

console.log(application.id, application.doc_checklist.missing);
```

## Patch application (upload docs, request submit)

Move a `DRAFT` toward `SUBMITTED` by attaching documents, or transition once complete.

```
PATCH /developers/lending/v1/applications/{id}
```

**Request**:

```json
{
  "documents": [
    { "type": "settlement_history_90d", "psp": "stripe", "auto_pull": true }
  ],
  "submit": true
}
```

`auto_pull: true` tells the platform to pull the settlement-history document from the
InventoryOS Stream 7 projection instead of requiring an upload. Available for PSP-linked
documents only.

**Response (`200 OK`)**:

```json
{
  "id": "lapp_2qZf…",
  "state": "SUBMITTED",
  "doc_checklist": {
    "required": ["merchant_identity", "psp_account_link", "settlement_history_90d"],
    "received": ["merchant_identity", "psp_account_link", "settlement_history_90d"],
    "missing": []
  },
  "submitted_at": "2026-06-01T12:05:00.000Z"
}
```

### curl

```bash
curl -X PATCH https://apiv3.droplinked.com/developers/lending/v1/applications/lapp_2qZf... \
  -H "Authorization: Bearer ds_test_REPLACE_ME" \
  -H "Content-Type: application/json" \
  -d '{
    "documents": [
      { "type": "settlement_history_90d", "psp": "stripe", "auto_pull": true }
    ],
    "submit": true
  }'
```

### TypeScript

```ts
import { DroplinkedClient } from "@droplinked/sdk";

const droplinked = new DroplinkedClient({
  apiKey: process.env.DROPLINKED_API_KEY ?? "ds_test_REPLACE_ME",
});

const submitted = await droplinked.lending.applications.update("lapp_2qZf...", {
  documents: [{ type: "settlement_history_90d", psp: "stripe", autoPull: true }],
  submit: true,
});
```

## List applications

```
GET /developers/lending/v1/applications
```

Filter by state, cohort, tier, or referrer.

| Param | Type | Notes |
|---|---|---|
| `state` | string | Optional |
| `cohort` | string | Optional |
| `tier` | string | Optional (`Tier1_CredibleX`, `Tier2_USLFI`, `Tier3_Vault`) |
| `referrer_id` | string | Optional; partner-scoped |
| `submitted_since` | ISO-8601 | Optional |
| `limit` | int | Max 200, default 50 |
| `cursor` | string | Opaque pagination token |

### curl

```bash
curl "https://apiv3.droplinked.com/developers/lending/v1/applications?state=SUBMITTED&tier=Tier1_CredibleX" \
  -H "Authorization: Bearer ds_test_REPLACE_ME"
```

### TypeScript

```ts
import { DroplinkedClient } from "@droplinked/sdk";

const droplinked = new DroplinkedClient({
  apiKey: process.env.DROPLINKED_API_KEY ?? "ds_test_REPLACE_ME",
});

const page = await droplinked.lending.applications.list({
  state: "SUBMITTED",
  tier: "Tier1_CredibleX",
  limit: 50,
});
```

## Post decision (lender only)

Lender partners with `lending:decide` scope transition a `SUBMITTED` (or `UNDER_REVIEW`)
application to `APPROVED` or `REJECTED`.

```
POST /developers/lending/v1/applications/{id}/decisions
```

**Request (approval)**:

```json
{
  "decision": "APPROVED",
  "approved_amount": "45000.00",
  "approved_term_months": 12,
  "apr": "0.149",
  "disbursement_method": "usdc_to_wallet",
  "wallet_address": "0xMerchantPayoutWallet…",
  "notes": "Strong sell-through + DPP coverage; haircut on requested amount."
}
```

**Request (rejection)**:

```json
{
  "decision": "REJECTED",
  "reason_code": "INSUFFICIENT_SELL_THROUGH_HISTORY",
  "notes": "Less than 60 days of settlement history; resubmit at 90d."
}
```

Valid `reason_code` values:

| Code | Meaning |
|---|---|
| `INSUFFICIENT_SELL_THROUGH_HISTORY` | < 90 days of settlement data |
| `LGD_EXCEEDS_TIER_LIMIT` | Risk model output above tier underwriting policy |
| `KYB_INHERITANCE_GAP` | Cohort-required KYB source missing |
| `RETURN_RATE_ELEVATED` | 30d return rate above shop-class threshold |
| `JURISDICTIONAL_MISMATCH` | Tier cannot lend to merchant's jurisdiction |
| `OTHER` | Free-text required in `notes` |

**Response (`200 OK`)**:

```json
{
  "id": "lapp_2qZf…",
  "state": "APPROVED",
  "decision": {
    "decision": "APPROVED",
    "approved_amount": "45000.00",
    "approved_term_months": 12,
    "apr": "0.149",
    "decided_at": "2026-06-02T15:00:00.000Z",
    "decided_by": "creblex_underwriter_4"
  }
}
```

### curl

```bash
curl -X POST https://apiv3.droplinked.com/developers/lending/v1/applications/lapp_2qZf.../decisions \
  -H "Authorization: Bearer ds_test_REPLACE_ME" \
  -H "Content-Type: application/json" \
  -d '{
    "decision": "APPROVED",
    "approved_amount": "45000.00",
    "approved_term_months": 12,
    "apr": "0.149",
    "disbursement_method": "usdc_to_wallet",

```

## Errors

Standard error envelope:

```json
{
  "error": {
    "code": "INVALID_STATE_TRANSITION",
    "message": "Cannot decide on application in state DRAFT — submit first.",
    "details": { "current_state": "DRAFT", "attempted_transition": "decision" }
  }
}
```

| Code | HTTP | Cause |
|---|---|---|
| `INVALID_STATE_TRANSITION` | 409 | State machine rejects the action |
| `DOC_CHECKLIST_INCOMPLETE` | 422 | `submit: true` with missing docs |
| `COHORT_MISMATCH` | 422 | Document doesn't match the cohort's expected sources |
| `SCOPE_DENIED` | 403 | Key lacks `lending:decide` or `lending:submit` |
| `RATE_LIMITED` | 429 | Beyond write-class quota |

## Webhooks

Application transitions emit webhook events to lender-partner subscriptions:

| Event | When |
|---|---|
| `lending.application.submitted` | DRAFT → SUBMITTED |
| `lending.application.under_review` | SUBMITTED → UNDER_REVIEW |
| `lending.application.decided` | UNDER_REVIEW → APPROVED \| REJECTED |
| `lending.application.disbursed` | APPROVED → DISBURSED |

Subscribe via the InventoryOS webhook subscription endpoint (same HMAC verification, same DLQ
semantics — see [Webhook subscriptions](/developers/inventory-os-api/subscriptions)).
