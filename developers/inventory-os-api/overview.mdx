**InventoryOS** is Droplinked's headless inventory data layer. The same SKU + provenance +
stock-level + sell-through record simultaneously serves five orthogonal consumer surfaces — a
lending underwriter, an agentic buyer surface, a merchant program builder, a 3PL partner, and a
compliance gate — without the surfaces ever speaking to each other.

The API is the partner-facing surface of that layer. You read streams, register for webhook
deliveries, and stitch InventoryOS into your own systems.

## The five consumer surfaces

| Surface | Streams consumed | Typical integrator |
|---|---|---|
| **Lending underwriter** | 2, 3, 4, 7, 8 | CredibleX, US LFI corridor lenders, Tier-3 vault partners |
| **Agentic buyer discovery** | 1, 2, 5, 8 | MCP clients, ACP-feed consumers, x402 buyers |
| **Merchant program builder** | 1, 5, 6, 7 | Affiliate engine, dynamic-pricing, lending eligibility UX |
| **3PL data partner** | 2, 3, 4 outbound; 8 inbound | Stord, Flowspace, ShipHero |
| **Compliance gate** | 6, 7, 8 | FTC engine, 1099-NEC export, AML/Travel Rule |

You only need the streams that map to your surface. A lender doesn't need attribution (6); a 3PL
doesn't need settlement (7); an agentic buyer doesn't need return-rate (4).

## Why the data layer is multi-purpose

The same canonical record powers multiple surfaces because the streams are produced once and
**projected** into per-surface read models. A merchant updates a SKU once — the catalog stream
(1) emits, which fans out to the ACP feed (surface D), the lending collateral catalog
(surface A), the affiliate program builder (surface B), the 3PL partner sync (surface E), and
the compliance audit trail (surface C). The integrator subscribes to streams; the projection
handles fan-out.

## Auth + scopes (quick recap)

- All endpoints require an `inventory:read` scoped API key (`ds_test_…` or `ds_live_…`).
- Webhook subscriptions additionally require `inventory:webhooks`.
- Send the key as `Authorization: Bearer ds_test_REPLACE_ME`.

See [Getting started](/developers/getting-started) for full auth, scopes, rate limits, and
cursor pagination.

## Base path

```
https://apiv3.droplinked.com/developers/inventory/v1
```

Every stream endpoint lives under `/streams/{name}`; webhook management under `/subscriptions`.

## Webhook subscriptions

Most integrators don't poll — they subscribe. Register a callback URL and a stream filter; we
deliver signed JSON envelopes with HMAC-SHA256 verification, exponential backoff retry, and a
dead-letter queue you can replay.

See [Webhook subscriptions](/developers/inventory-os-api/subscriptions) for the verification
recipe (Node.js sample included) and event payload shape.

## Versioning

Versioning is per-stream and date-tagged. Pass `X-InventoryOS-Version: 2026-06-01` on every
request. We support N-2 prior versions (so this version is supported through `2026-08-01`).
Breaking changes ship behind a new version date; non-breaking additions ship inline.
