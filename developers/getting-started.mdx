## Authentication

Partner endpoints use a **partner API key** with explicit scopes — not a merchant JWT. Keys are
prefixed `ds_test_…` (development sandbox) or `ds_live_…` (production). Send them as a Bearer
header.

```bash
curl https://apiv3.droplinked.com/developers/inventory/v1/streams/catalog \
  -H "Authorization: Bearer ds_test_REPLACE_ME"
```

```ts
import { DroplinkedClient } from "@droplinked/sdk";

const droplinked = new DroplinkedClient({
  apiKey: process.env.DROPLINKED_API_KEY ?? "ds_test_REPLACE_ME",
  baseUrl: "https://apiv3.droplinked.com",
});

const page = await droplinked.inventory.catalog.list({ limit: 50 });
```

### Scopes

| Scope | Grants |
|---|---|
| `inventory:read` | Read any InventoryOS stream (catalog, inventory level, sell-through, return rate, pricing, attribution, settlement, provenance) |
| `inventory:webhooks` | Register and consume webhook subscriptions for inventory streams |
| `lending:submit` | Submit and update a lending application as a referrer/partner |
| `lending:read` | Read a lending application's status, doc checklist, and decisions |
| `lending:decide` | Post an underwriter decision (CredibleX-tier or Tier-3 vault partners only) |
| `kyb:read` | Read a merchant's KYB cohort, MoR entity, and inheritance chain |

Scopes are additive. Issue separate keys for separate integration responsibilities — don't mint
one omni-scope key.

## Rate limits

| Endpoint class | Default | Burst |
|---|---|---|
| Read (any `GET /developers/*`) | 600 req/min/key | 1200 req over 5s |
| Write (`POST` / `PATCH` lending) | 60 req/min/key | 120 req over 5s |
| Webhook subscription management | 30 req/min/key | 60 req over 5s |

Limits are returned per response:

```
X-RateLimit-Limit: 600
X-RateLimit-Remaining: 587
X-RateLimit-Reset: 1717200000
```

A `429 Too Many Requests` returns `Retry-After` in seconds. Back off and resume.

## Pagination

All list endpoints use **opaque cursor pagination**. Pass `?limit=` (max 200) and follow
`next_cursor` until it's absent.

```bash
curl "https://apiv3.droplinked.com/developers/inventory/v1/streams/catalog?limit=50&cursor=eyJpZCI6IjY1ZGY4LiJ9" \
  -H "Authorization: Bearer ds_test_REPLACE_ME"
```

Response envelope:

```json
{
  "data": [ /* page of items */ ],
  "next_cursor": "eyJpZCI6IjY1ZGY5LiJ9",
  "generated_at": "2026-06-01T12:00:00.000Z"
}
```

Cursors are tied to a key and a stream — don't reuse cursors across keys.

## Environments

| Environment | Base URL | API keys |
|---|---|---|
| Production | `https://apiv3.droplinked.com` | `ds_live_…` |
| Development | `https://apiv3dev.droplinked.com` | `ds_test_…` |

Data is isolated per environment. Build and test against development; promote to production with
new live keys.

## Issuing keys

API keys are minted from the merchant or partner dashboard at
`https://droplinked.com/dashboard/developers` (BETA, behind feature flag). For Tier-1
CredibleX referral keys and Tier-3 vault decisioning keys, contact
[partners@droplinked.com](mailto:partners@droplinked.com).
